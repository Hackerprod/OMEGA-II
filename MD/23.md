SOL — T0.0 Hardware Inventory Closures
1. Definiciones
POPULATED_DIMM_COUNT
= número de módulos físicos de memoria presentes.

POPULATED_CHANNEL_COUNT
= número de canales de memoria que el firmware/topología estática
  reporta como ocupados.

STATIC_MEMORY_TOPOLOGY
= información de SMBIOS/WMI/firmware obtenida sin benchmark.

BW_D(n)
= ancho de banda DRAM sostenido medido con n workers.

POWER_LIMIT_VISIBILITY
= capacidad de leer explícitamente PL1/PL2 mediante las interfaces
  permitidas en T0.0.
2. RAM — canales poblados
DECISIÓN

Para el inventario T0.0-a gobierna la información de SMBIOS/WMI del firmware, no la interpretación de SEP -platform-info.

Registrar:

POPULATED_DIMM_COUNT = 2

DIMM_0:
  16 GiB
  DDR5-5200
  DataWidth = 64
  locator = Controller0-DIMM1

DIMM_1:
  16 GiB
  DDR5-5200
  DataWidth = 64
  locator = Controller1-DIMM1

POPULATED_CHANNEL_COUNT = 2
source = SMBIOS/WMI firmware topology
status = FIRMWARE_REPORTED

La salida de SEP:

package0/controller0/channel0
→ muestra ambos DIMMs

resto vacío

se conserva como:

SEP_MEMORY_TOPOLOGY = CONFLICTING_OBSERVATION

y no invalida por sí sola el inventario firmware.

Razón: SEP ya está operando con una base de eventos/reporting cuya nomenclatura no debe reinterpretarse como autoridad física superior a SMBIOS para la ocupación de slots/canales.

2.1 BW_D

Sí: BW_D(n) en T0.0-f debe usarse como corroboración complementaria, no como sustituto del inventario.

Por tanto:

STATIC_MEMORY_TOPOLOGY
→ responde cuántos canales reporta ocupados el firmware.

BW_D(n)
→ responde qué ancho de banda efectivo entrega la plataforma.

No inferir retroactivamente:

"BW observado = exactamente X canales"

como prueba única de topología.

Si el BW medido fuese materialmente incompatible con una configuración dual-channel esperada, se registra una discrepancia para investigación posterior; no se reescribe el inventario automáticamente.

DECISIÓN RAM = CLOSED.

3. PL1 / PL2
DECISIÓN: ACEPTAR PROPUESTA

No instalar drivers adicionales ni leer MSR sólo para obtener PL1/PL2 en T0.0.

Registrar:

PL1 = UNAVAILABLE_WITH_ALLOWED_INTERFACES
PL2 = UNAVAILABLE_WITH_ALLOWED_INTERFACES

POWER_LIMIT_VISIBILITY = NOT_AVAILABLE

con las interfaces intentadas:

WMI
systeminfo
SEP
powercfg

y su resultado negativo.

Esto cierra el campo; no queda como TBD-MEASURE.

3.1 Caracterización dinámica

T0.0-i debe registrar, bajo carga controlada:

frecuencia efectiva sostenida
frecuencia mínima/máxima observada
temperatura, si existe sensor permitido
potencia, si alguna interfaz ya disponible la expone
duración de la carga
número/tipo de workers

Si temperatura o potencia tampoco son accesibles:

TEMPERATURE_TELEMETRY = UNAVAILABLE
POWER_TELEMETRY = UNAVAILABLE

sin convertirlo en fallo automático de T0.0.

La evidencia dinámica responde:

"¿el CPU sostiene el régimen de ejecución usado?"

pero no se utiliza para inventar valores de PL1/PL2.

DECISIÓN PL1/PL2 = CLOSED.

4. Formato sintético Q4 / activaciones / ISA_REF
DECISIÓN: RATIFICAR

Para T0.0 queda ratificado:

Q4_GROUP = 32 pesos

Q4_GROUP_BYTES = 18
  16 B nibbles signed [-7,+7]
  2 B scale FP16 little-endian

q_eff = 18/32 = 0.5625 B/peso

Activaciones:

INT8 symmetric
scale FP32
grupo = 32 activaciones

La definición matemática es la misma para:

AVX2
AVX-VNNI

Las dos rutas deben implementar el mismo operador; sólo cambia la implementación ISA.

Referencia:

ISA_REF = scalar correctness reference

y no participa como competidor de rendimiento.

5. Repeticiones y calentamiento
DECISIÓN: ACEPTAR CON UNA REGLA

El JUEZ puede fijar:

N >= 30
warmup_count
estadístico central
estadístico de dispersión

antes de ejecutar cada familia de medición.

Una vez iniciada una familia:

N
warmup_count
orden
estadísticos
criterios de descarte

quedan congelados y no pueden modificarse tras observar resultados.

Valor recomendado:

N = 31
estadístico central = mediana
dispersión = IQR + MAD

por evitar empate par y mantener robustez frente a outliers.

Esto es implementación de medición, no nueva hipótesis científica.
