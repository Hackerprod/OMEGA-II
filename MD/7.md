3b. AMB-57(b) — MODIFICAR LIGERAMENTE

Ratifico el campo:

encoder_entry_points

pero no basta con que la lista sea no vacía.

Cada entrada debe ser:

{
  file,
  symbol,
  file_sha256,
  role = "SOURCE_WEIGHTS_TO_CONTRACT_Q4"
}

y el auditor independiente debe verificar que:

file y symbol existen en los bytes manifestados;

el símbolo es alcanzable por la build congelada;

su función declarada es convertir pesos fuente al Q4 contractual, no sólo cargar/copiar/decodificar Q4.

Entonces:

kernel_has_encoder = true
iff
existe >=1 entry auditado con
role="SOURCE_WEIGHTS_TO_CONTRACT_Q4".

Si la semántica de un entry point no puede determinarse inequívocamente:

NO_LAUNCH
subcause=KERNEL_ENCODER_IDENTITY_AMBIGUOUS

No se infiere true por nombre de símbolo.

3c. AMB-57(c) — MODIFICAR: rango 1 NO ejecuta 5.4 oficial

Ésta es la opción más limpia.

Si existe R1:

PLATFORM_INVENTORY_MISMATCH

entonces:

5.4 official correctness = NOT_EXECUTED
kernel_status            = NOT_EVALUATED
kernel_correctness       = NOT_EVALUATED
kernel_rebuild_required  = NOT_EVALUATED

No se produce evidencia T0 del kernel en una plataforma que ya falló su identidad contractual.

Por tanto la excepción de P-22b:

"salvo correctness de 5.4"

se restringe explícitamente a:

R2 = MEASUREMENT_STACK_INVALID

En R2, correctness sí puede ejecutarse porque el hardware objetivo ya fue validado y el fallo pertenece al stack de medición. Si steps1-7 producen un FAIL válido:

kernel_status           = NOT_QUALIFIED
kernel_correctness      = FAIL
kernel_rebuild_required = true

aunque el terminal principal siga siendo MEASUREMENT_STACK_INVALID.

Si se desea probar el kernel bajo una plataforma R1 por razones de ingeniería, sólo puede hacerse como:

DIAGNOSTIC_ONLY
EVIDENTIARY_WEIGHT=ZERO

fuera de la subunidad oficial 5.4.

AMB-57(c) CLOSED.

Racional
Rango 1

Un fallo de identidad/topología significa que no estamos midiendo la plataforma contractual. Permitir una adjudicación científica del kernel allí contradice directamente la regla NOT_BARE_METAL / wrong target → no T0 evidence.

Rango 2

Un MSI puede deberse a contadores, idle, pinning u otra instrumentación. Eso no necesariamente invalida una prueba numérica independiente de correctness; por tanto conservar esa evidencia evita perder información legítima.

Encoder

lista no vacía es condición sintáctica; entry point auditado que realmente implementa source→Q4 es la condición semántica necesaria.
