3. AMB-64(b) — MODIFICAR

No usar un único mapa artifact_evidentiary_status que mezcle GOVERNANCE_OFFICIAL con peso científico.

Cada artefacto relevante lleva dos ejes independientes:

artifact_status[artifact] = {
  custody_status,
  evidentiary_status
}
Custodia
custody_status ∈ {
  GOVERNANCE_OFFICIAL
}

Todo artefacto incorporado al manifest oficial y preservado por la cadena de hashes puede ser GOVERNANCE_OFFICIAL.

Peso evidencial
evidentiary_status ∈ {
  OFFICIAL_T0,
  OFFICIAL_PLATFORM_RECORD,
  DIAGNOSTIC_ONLY,
  NOT_APPLICABLE
}

Ejemplos:

inventario que establece R1:
custody_status    = GOVERNANCE_OFFICIAL
evidentiary_status= OFFICIAL_PLATFORM_RECORD

resultado 5.3 producido antes de un R1 tardío:
custody_status    = GOVERNANCE_OFFICIAL
evidentiary_status= DIAGNOSTIC_ONLY

resultado T0 válido sin R1:
custody_status    = GOVERNANCE_OFFICIAL
evidentiary_status= OFFICIAL_T0

Así “oficial” como registro nunca implica automáticamente “válido como evidencia positiva”.

6. AMB-64(e) — MODIFICAR

No confirmo que “empezó 5.4” deba llamarse simplemente EXECUTED; pierde información importante sobre una interrupción parcial.

Usar:

official_correctness_5_4 =
  NOT_EXECUTED
  STARTED_NOT_COMPLETED

Mapeo

→ no comenzó ningún paso oficial de correctness.

→ comenzó 5.4 pero no terminó el conjunto necesario

II. RACIONAL
Custodia vs evidencia

Un archivo puede ser absolutamente oficial, hash-bound y necesario para auditoría mientras su contenido tiene EVIDENTIARY_WEIGHT=ZERO. Mezclar ambos conceptos en un solo token habría hecho ambiguos los resultados degradados por un R1 tardío.

Correctness parcial

Un REFERENCE_DISAGREEMENT o una interrupción puede producir muchos datos crudos útiles, pero no una afirmación PASS/FAIL. Por eso OFFICIAL_T0 debe reservarse a una adjudicación válida.

Estado de ejecución

STARTED_NOT_COMPLETED permite distinguir mecánicamente:

nunca se ejecutó
vs
se ejecutó parcialmente
vs
se completó.

Esa distinción es necesaria para una tabla de precedencia realmente ejecutable.
