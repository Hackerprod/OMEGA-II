Definiciones
formal_MD_body
= contenido comprendido dentro del bloque formal del dictamen MD/N.

correctness_adjudicated
= resultado factual producido por la rutina de correctness:
  PASS | FAIL | NOT_ADJUDICATED.

artifact_status[a]
= {
    custody_status,
    evidentiary_status
  }
para el artefacto a.
I. DECISIONES
1. Regla de proceso — ACEPTAR, reforzada

A partir de este dictamen:

SOLO formal_MD_body es normativo.

Cualquier texto:

posterior al cierre del bloque formal;

generado por interfaz;

sugerencia no incluida dentro de una sección del MD;

línea suelta fuera del cuerpo formal;

es:

NON_NORMATIVE_INTERFACE_TEXT

y:

NO genera AMB
NO modifica spec
NO requiere implementación

Para que una regla sea normativa debe aparecer dentro del formal_MD_body.

Esto aplica prospectivamente y cierra el bucle de ambigüedades artificiales.

2. AMB-65 — CERRAR

Las dos líneas que originaron AMB-65 quedan clasificadas bajo la nueva regla como:

NON_NORMATIVE_INTERFACE_TEXT

No necesitan NORMATIVE_RESTATEMENT.

Si §14.3.1 ya las refleja inocuamente y sin introducir reglas nuevas, puede permanecer; no adquiere autoridad adicional por esas líneas.

AMB-65 CLOSED.

3. AMB-66 — ACEPTAR

EVIDENTIARY_WEIGHT no es una escala numérica general.

Dominio actual:

EVIDENTIARY_WEIGHT = ZERO

se aplica únicamente cuando el contenido está explícitamente clasificado:

DIAGNOSTIC_ONLY
ENGINEERING_SMOKE_ONLY

Para los demás estados:

OFFICIAL_T0
→ peso definido por el contrato/gate de su subunidad.

OFFICIAL_PLATFORM_RECORD
→ evidencia sólo de identidad/estado de plataforma;
  nunca implica PASS científico por sí sola.

NOT_APPLICABLE
→ no posee peso evidencial.

No añadir valores FULL, ONE, PARTIAL, etc.

AMB-66 CLOSED y no bloquea freeze.

4. AMB-67(a) — ACEPTAR

correctness_adjudicated conserva el resultado factual realmente producido incluso si aparece posteriormente R1.

Ejemplo:

correctness_adjudicated = FAIL
correctness_result_raw  = preservado
R1 tardío               = true

Entonces:

correctness_evidentiary_status = DIAGNOSTIC_ONLY

kernel_status           = NOT_EVALUATED
kernel_correctness      = NOT_EVALUATED
kernel_rebuild_required = NOT_EVALUATED

No hay contradicción:

correctness_adjudicated
= qué produjo la rutina

kernel_status final
= qué puede afirmarse oficialmente al cierre

AMB-67(a) CLOSED.

5. AMB-67(b) — ACEPTAR

Artefactos puramente de gobernanza:

manifest
hash registries
ledger
verdict
terminal/substates
authorization/preflight custody records

usan:

custody_status     = GOVERNANCE_OFFICIAL
evidentiary_status = NOT_APPLICABLE

salvo que un artefacto contenga además una medición específica que tenga un estatus propio separado.

Inventarios 5.1

Con o sin R1:

custody_status     = GOVERNANCE_OFFICIAL
evidentiary_status = OFFICIAL_PLATFORM_RECORD

porque su función científica es establecer la identidad/estabilidad de plataforma, no demostrar el mecanismo H0.

Si esos inventarios establecen R1 siguen siendo OFFICIAL_PLATFORM_RECORD; simplemente la conclusión de plataforma es negativa.

AMB-67(b) CLOSED.

6. AMB-67(c) — ACEPTAR

artifact_status se aplica sólo a artefactos incorporados a la cadena oficial del run/freeze.

Artefactos externos:

QA_ONLY
scratch
engineering diagnostics
temporary fixtures

no reciben artifact_status, salvo que posteriormente sean formalmente incorporados al manifest oficial.

Los términos:

artifact_custody_status
artifact_evidentiary_status

son nombres conceptuales de los dos subcampos:

artifact_status[a].custody_status
artifact_status[a].evidentiary_status

No crear campos duplicados.

AMB-67(c) CLOSED.

7. AMB-67(d) — ACEPTAR

La división:

A5a / A5b

y el caso:

A2 → official_correctness_5_4 = COMPLETED

quedan confirmados cuando, conforme a MD/414, la rutina aplicable terminó y produjo adjudicación válida.

No se infiere COMPLETED sólo porque 5.4 fue invocada; debe satisfacer la definición formal de MD/414.

AMB-67(d) CLOSED.

8. Corrección (i) — CONFIRMADA

Si existe R1 al cierre:

kernel_status
kernel_correctness
kernel_rebuild_required

quedan NOT_EVALUATED, con prioridad sobre el mapeo ordinario de PASS/FAIL del kernel.

El resultado factual anterior se conserva mediante:

correctness_adjudicated
correctness_result_raw
diagnostic_substates

según corresponda.

9. Corrección (ii) — CONFIRMADA

En tabla A:

A2

es una adjudicación completada cuando sus condiciones aplicables se cumplieron.

Las correcciones:

T01/T02 → COMPLETED(A1)
T05/T13 → A1 o A3

según la semántica descrita por la auditoría quedan confirmadas.

II. RACIONAL
Resultado factual vs afirmación oficial

Preservar correctness_adjudicated=FAIL bajo R1 es útil para diagnóstico y auditoría. Convertirlo en kernel_status=NOT_QUALIFIED sería distinto: eso sí sería una conclusión oficial T0 sobre una plataforma que terminó inválida.

Gobernanza no es evidencia positiva

Un SHA manifest puede ser absolutamente oficial sin demostrar ninguna hipótesis. Separar custodia de peso científico evita que GOVERNANCE_OFFICIAL se interprete como “evidencia favorable”.

Regla de proceso

La fuente normativa debe tener un límite sintáctico inequívoco. Desde ahora ese límite es el cuerpo formal del MD. Esto elimina definitivamente el patrón de crear AMB a partir de texto incidental de interfaz.
