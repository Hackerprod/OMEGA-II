2. AMB-62(a) — ACEPTAR

Mapeo:

si existe correctness_result_raw
AND no existe R1 al cierre:
    correctness_evidentiary_status = OFFICIAL_T0

si existe correctness_result_raw
AND existe R1 al cierre:

si correctness_result_raw = NONE:
    correctness_evidentiary_status = NOT_APPLICABLE

Esto elimina todos los — ambiguos de las tablas.

AMB-62(a) CLOSED.

3. AMB-62(b) — MODIFICAR

La pérdida de peso evidencial bajo un R1 tardío sí se extiende a los resultados científicos previamente producidos, pero no a todos los artefactos administrativos.

Si al cierre existe R1:

resultados derivados de 5.2, 5.3, 5.4 y 5.5
que pretendan medir/calificar propiedades T0
→ DIAGNOSTIC_ONLY
→ EVIDENTIARY_WEIGHT=ZERO

Pero:

capturas de inventario 5.1
→ OFFICIAL_PLATFORM_RECORD

porque son precisamente la evidencia que establece R1.

Asimismo permanecen oficiales, como artefactos de gobernanza:

hash manifests
raw files
preflight records
ledger
verdict
terminal/substates

aunque no constituyan evidencia positiva para T0.

No se borra ni reescribe ningún resultado anterior.

AMB-62(b) CLOSED.

4. AMB-62(c) — ACEPTAR

Si una interrupción impide completar el cierre:

inventory_stability = NOT_ESTABLISHED

para las capturas faltantes.

El terminal utiliza sólo condiciones realmente establecidas; normalmente será:

ABORTED_NO_VERDICT

si no existe un terminal de mayor prioridad.

Un retry técnico autorizado según MD/406 vuelve a ejecutar las capturas requeridas; no se reutiliza una captura inexistente ni se supone estabilidad.

AMB-62(c) CLOSED.

5. AMB-62(d) — ACEPTAR CON PRECISIÓN

La enumeración PRE-RUN puede ejecutarla:

JUEZ
OR implementador delegado por el JUEZ

La custodia/freeze corresponde al JUEZ.

Debe existir un registro hash-bound de:

comandos ejecutados
versiones
stdout/stderr crudos
exit codes
artefactos enumerados

Sólo están permitidas operaciones de:

version
capability enumeration
event listing
driver/status inspection
metadata/documentation lookup local

Prohibido:

benchmark
workload de carga
comparación cache/DRAM
contador integrado sobre carga
medición de BW
medición de latencia
selección basada en rendimiento

El auditor independiente debe comprobar que:

instrumentation_selection_freeze.json contiene únicamente los campos permitidos;

los comandos ejecutados pertenecen al conjunto read-only anterior;

no hubo workload/benchmark;

no aparecen resultados de performance como criterio de selección.

Timestamps administrativos incidentales en logs son permitidos; lo prohibido son medidas de rendimiento.

Fallo de esta auditoría:

NO_LAUNCH
subcause=INSTRUMENTATION_SELECTION_NOT_INDEPENDENT

AMB-62(d) CLOSED.

6. AMB-62(e) — MODIFICAR

Bajo R2, con R1 ausente:

Pasos 1–7
steps 1-7 = técnicamente ejecutables

si preflight de inputs/referencias sigue válido.

Paso 8

Definir:

AFFINITY_INVALIDATING_R2 =
  PINNING_FAIL
  OR cualquier subcausa que demuestre que
     la afinidad requerida no puede verificarse/mantenerse.

Entonces:

si AFFINITY_INVALIDATING_R2:
    step8 = NOT_EVALUATED
else:
    step8 puede ejecutarse normalmente

No usar el nombre genérico VIRTUALIZATION_BLOCKS por sí solo: si virtualización bloquea PMU pero la afinidad está validada, step8 no queda automáticamente invalidado.

Paso 9

Siempre:

si R2:
    step9 PERF_INFORMATIVO = NOT_EXECUTED

AMB-62(e) CLOSED.
