b) Despacho: eliminar Python de la medición, no restarlo

La referencia gobernante será LibTorch/ATen desde C++, sin autograd. ATen es la biblioteca de operaciones subyacente a las interfaces Python y C++ de PyTorch. 
PyTorch Docs

Se cronometra un bloque de R llamadas sucesivas, con R calibrado antes de las 31 réplicas. R es repetición metrológica, no K arquitectónico ni multiplicación de los slots. QA/desensamblado debe demostrar que las llamadas no fueron eliminadas o fusionadas para reducir trabajo.

No se resta overhead estimado. El despacho nativo de ATen permanece incluido; el coste de Python puede reportarse separadamente como diagnóstico. torch.compile no es obligatorio; una ruta compilada solo participa si queda preregistrada y conserva el trabajo.

Versión, backend efectivo, rutas candidatas y regla de selección —la más rápida cualificada por celda— quedan congelados antes de afinar OMEGA.

BF16 no gobierna esta comparación. Se exige cálculo FP32 completo, sin reducción interna silenciosa a BF16/TF32; PyTorch dispone de controles de precisión específicos del backend. 
PyTorch Docs

Una ruta INT8 solo es admisible si conserva productos por grupo, acumulación INT32 exacta y escalado/reducción correspondientes, contabilizando todo su coste. Una _int_mm que ignore esas escalas no es equivalente.

La expansión/prepacking estático de pesos de PyTorch se permite fuera del timer y se contabiliza; la preparación dinámica se paga por aplicación. FP32 tiene distinta huella: esta comparación evalúa velocidad del mismo operador, no igualdad de tráfico ni residencia.
