OMEGA MD/424 — PRE-RUN Instrumentation and Manifest Format Rulings
0. Definiciones
SOURCE_SET
= conjunto completo de archivos que determinan el binario contractual:
  fuentes, headers propios y archivos de build manifestados.

SOURCE_SET_AGGREGATE_SHA
= hash determinista de la identidad completa de SOURCE_SET.

VTUNE_PRODUCT_VERSION
= versión pública del producto.

VTUNE_PACKAGE_VERSION
= versión del paquete/installer cuando pueda verificarse.

VTUNE_INTERNAL_BUILD
= build interno que reporta la instalación local.

INSTRUMENTATION_CANDIDATE
= ruta/evento seleccionado PRE-RUN por disponibilidad y semántica,
  todavía no calificado experimentalmente.

INSTRUMENTATION_VALID
= ruta que posteriormente supera los controles oficiales de T0.0.2.
I. CAMPOS DE FORMATO (a)–(c)
1. kernel_cases_manifest: schema, IDs y seeds — DELEGADO AL JUEZ

ACEPTO que el JUEZ decida estos detalles sin volver a Sol, siempre que cumplan:

schema_version explícito;
IDs únicos y deterministas;
semillas explícitas, nunca implícitas;
serialización reproducible;
ningún ID/seed modifica una distribución o criterio científico;
ningún valor se genera a partir de resultados observados.

El JUEZ puede escoger nombres concretos.

Cambiar posteriormente sólo el nombre/formato de un ID, preservando exactamente la semántica, es cambio mecánico; cambiar qué fixture representa o cómo se genera es cambio contractual.

2. SOURCE_SET aggregate — MODIFICAR

No acepto como identidad gobernante:

concatenación cpp + build.cmd

si SOURCE_SET contiene más archivos.

El aggregate debe cubrir todo SOURCE_SET.

Formato recomendado y normativo:

1. ordenar entradas por path relativo normalizado, ASCII ascendente;

2. para cada entrada crear:
   {
     path,
     size_bytes,
     sha256
   }

3. serializar la lista en JSON canónico ya usado por el proyecto;

4. SOURCE_SET_AGGREGATE_SHA
   = SHA256(bytes exactos de esa serialización).

No hashear contenido concatenado sin delimitación.

Las copias BUILD_A/BUILD_B no pertenecen a SOURCE_SET; son outputs reproducibles y se enumeran por separado.

3. instrumentation_selection_freeze subcampos — DELEGADO CON LÍMITE

El JUEZ puede decidir nombres/subcampos mecánicos.

Pero instrumentation_selection_freeze.json debe permanecer semánticamente limitado a lo autorizado por MD/412:

versiones/builds;
drivers/disponibilidad;
rutas candidatas DRAM/IMC;
evento/métrica candidata L2;
unidades;
semántica documental;
comandos/configuración;
hashes/procedencia.

Las observaciones crudas adicionales deben ir preferentemente en:

raw_enumeration_log

externo y hash-bound, referenciado por el freeze.

No incluir dentro del freeze:

bandwidth observado;
latencia;
timings comparativos;
A/A;
cache-vs-DRAM;
resultado de causalidad;
ningún dato que implique VALID.

El freeze selecciona candidatos; T0.0.2 los valida.

III. INTEL PCM
5. Ruling (e) — PCM PUEDE QUEDAR NOT_AVAILABLE

ACEPTO.

Si PCM no está instalado y no se necesita para completar el stack:

PCM = NOT_AVAILABLE

puede congelarse así.

Seleccionar:

VTune Memory Access

como:

DRAM_IMC_CANDIDATE

no como VALID.

La condición antes de RUN_AUTH sigue siendo:

>=1 candidato DRAM/IMC seleccionable
AND
>=1 observable causal L2 seleccionable

y dentro del run deben convertirse experimentalmente en:

VALID

según REV25.

PCM no es requisito nominal.

No instalar PCM únicamente para tener una segunda herramienta si VTune cubre las dos observabilidades requeridas.

Continúa vigente:

driver oficial + firma válida → instalación permitida;
test-signing / driver no firmado → HOLD.
