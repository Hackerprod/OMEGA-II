I. AMB-71 — INPUT CONTRACT VIOLATION DURANTE EL RUN
1. ACEPTAR CON PRECISIÓN

Si antes de crear el run_id se detecta cualquiera de:

Q4 no CANONICAL_Q4_VALID
activación no finita
OFFICIAL_FIXTURE_SHAPE fuera de SUPPORTED_SHAPE_DOMAIN
hash/input mismatch

entonces:

NO_LAUNCH
preflight_status = FIXTURE_SET_INVALID

Si una condición equivalente aparece después de iniciado el OFFICIAL_RUN, se establece:

ABORTED_NO_VERDICT
subcause = HARNESS_INPUT_DEFECT

salvo que al cierre exista un terminal de mayor prioridad, como R1 o R2.

En ese caso:

kernel_status           = NOT_EVALUATED
kernel_correctness      = NOT_EVALUATED
kernel_rebuild_required = NOT_EVALUATED

y nunca:

RETAINED_KERNEL_NOT_QUALIFIED

por ese defecto.

1.1 Responsabilidad de validación

El harness debe revalidar, antes de ejecutar cada fixture oficial:

hash/identidad del fixture
CANONICAL_Q4_VALID
finitud de activaciones
SUPPORTED_SHAPE_DOMAIN
tamaños de buffers

No es necesario repetir un SHA completo antes de cada llamada interna del mismo fixture si el buffer queda inmutable y su identidad ya quedó ligada al fixture antes de comenzar esa ejecución.

El kernel continúa sin obligación de validar bytes Q4 no canónicos.

AMB-71 CLOSED.

III. COMPARACIÓN ENTRE REFERENCIAS
3. ACEPTAR: COMPARAR EN y_acc64

La concordancia numérica entre las dos referencias independientes se determina antes de la conversión final a binary32.

Orden obligatorio:

1. q_a bit-exact
2. a_scale_fp32 bit-exact
3. comparar y_acc64_scalar vs y_acc64_torch
4. sólo después formar y_out

La comparación del punto 3 usa:

max_abs_ref <= 1e-9
nRMS_ref    <= 1e-10
3.1 No usar igualdad binary32 como criterio adicional de referencia

Una diferencia entre:

binary32_RNE(y_acc64_scalar)

y:

binary32_RNE(y_acc64_torch)

que derive únicamente de valores binary64 ya aceptados por el criterio 1e-9 / 1e-10 no crea por sí sola REFERENCE_DISAGREEMENT.

Eso evita que una diferencia microscópica alrededor de una frontera RNE convierta dos referencias float64 concordantes en falsamente discordantes.

3.2 Referencia gobernante para kernel-vs-reference

Manteniendo la jerarquía ya fijada desde MD/406:

contrato matemático
→ referencia escalar independiente
→ PyTorch float64 como cross-check independiente

una vez que el cross-check ha pasado:

y_out_ref
= binary32_RNE(y_acc64_scalar)

es la salida de referencia utilizada para la comparación formal contra el kernel.

PyTorch no se convierte en una segunda adjudicación competitiva del kernel.

Esto elimina cualquier ambigüedad de 1 ULP en la conversión final.

IV. PREFLIGHT DE FORMAS OFICIALES
4. ACEPTAR CON DEFINICIÓN MECÁNICA DE “M APROPIADA”

Añadir al preflight la comprobación:

cada OFFICIAL_FIXTURE_SHAPE
∈ SUPPORTED_SHAPE_DOMAIN

y exigir cobertura completa del núcleo d512.

Las formas de matriz son:

Wq     : O=512,  I=512
Wk     : O=512,  I=512
Wv     : O=512,  I=512
Wo     : O=512,  I=512
W_gate : O=2048, I=512
W_up   : O=2048, I=512
W_down : O=512,  I=2048

Para evitar que “M apropiada” quede abierta, exigir el producto cartesiano:

CANONICAL_MATRIX_ROLE × M_OFFICIAL

Por tanto el manifest debe contener cobertura oficial de:

7 roles × 6 valores M = 42 combinaciones

con:

M ∈ {1,2,4,8,16,32}.

Las cuatro matrices [512,512] siguen siendo roles separados aunque compartan las mismas dimensiones.

Si falta cualquiera de las 42 combinaciones requeridas:

FIXTURE_SET_INVALID
NO_LAUNCH

Esto no prohíbe fixtures adicionales de stress o QA dentro de SUPPORTED_SHAPE_DOMAIN.

VII. RACIONAL
7.1 HARNESS_INPUT_DEFECT

El kernel no debe ser penalizado por una entrada que el propio contrato prohíbe. Al mismo tiempo, un defecto descubierto después de comenzar el run impide continuar silenciosamente y por eso produce AB.

7.2 y_acc64

La independencia entre referencias debe comprobar la matemática de alta precisión, no el último redondeo binary32. El cast final pertenece al contrato observable del kernel, no al test de independencia float64.

7.3 Referencia escalar gobernante

Una segunda referencia sirve para detectar errores del oráculo principal. Una vez que ambas concuerdan dentro del criterio congelado, no conviene convertir una diferencia de redondeo final de 1 ULP en dos jueces rivales.

7.4 Cobertura d512

La forma contractual incluye M; por ello una presencia meramente nominal de las siete matrices no demuestra que las seis configuraciones de M utilizadas por correctness estén cubiertas.
