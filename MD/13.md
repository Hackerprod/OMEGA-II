I. PR_H1 — LAYOUT Q4
1. DECISIÓN: DEFINIR NORMATIVAMENTE AHORA

No delego el layout al JUEZ.

Debe integrarse en REV21.

1.1 Orientación matemática

Toda matriz se define como:

W.shape = [out_dim, in_dim]

y[o] = Σ_i W[o,i] * x[i]

El primer eje es salida.

El segundo eje es entrada.

1.2 Orden de matrices

El núcleo contractual contiene, en este orden exacto:

0 Wq     [ 512,  512]
1 Wk     [ 512,  512]
2 Wv     [ 512,  512]
3 Wo     [ 512,  512]
4 W_gate [2048,  512]
5 W_up   [2048,  512]
6 W_down [ 512, 2048]

Total:

P_core = 4,194,304 pesos

Los cuatro heads/proyecciones de atención no crean matrices de pesos adicionales; el split por heads ocurre después de las proyecciones correspondientes.

1.3 Eje de agrupación

Cada grupo Q4 contiene:

G = 32

pesos contiguos sobre in_dim dentro de una misma fila de salida.

Para:

W[o,i]

el grupo:

g

contiene:

i = 32g ... 32g+31

No se permite que un grupo cruce dos filas de salida.

Todas las dimensiones in_dim contractuales son divisibles exactamente por 32; no existen grupos tail.

1.4 Orden de grupos

Dentro de cada matriz:

for o = 0 .. out_dim-1
    for g = 0 .. in_dim/32-1
        emit group(o,g)

Es decir:

row-major por fila de salida,
luego group-index ascendente.
1.5 Layout exacto de un grupo

Cada grupo ocupa exactamente:

18 bytes

con:

bytes  0..15 = payload Q4
bytes 16..17 = scale IEEE binary16 little-endian

Para k=0..15:

byte[k].low_nibble  = q[2k]   & 0xF
byte[k].high_nibble = q[2k+1] & 0xF

donde:

q ∈ [-7,+7]

y la conversión a nibble es complemento a dos mediante:

q & 0xF

El scale es exactamente el definido por MD/406–407.

1.6 Padding del layout canónico

En Q4_CANONICAL_LAYOUT:

padding dentro de grupo  = 0
padding entre grupos     = 0
padding entre filas      = 0
padding entre matrices   = 0

Las siete matrices se concatenan directamente.

Offsets canónicos, en bytes desde el comienzo del núcleo:

Wq      =       0
Wk      = 147,456
Wv      = 294,912
Wo      = 442,368
W_gate  = 589,824
W_up    = 1,179,648
W_down  = 1,769,472
END     = 2,359,296

Por tanto:

B_core_payload = 2,359,296 B
q_eff_payload  = 0.5625 B/peso
1.7 Layout interno del kernel

El kernel puede utilizar KERNEL_EXEC_LAYOUT distinto para alineamiento, SIMD o repacking, pero sólo si:

1. deriva determinísticamente de Q4_CANONICAL_LAYOUT;
2. la transformación es lossless respecto de q y scale;
3. existe test round-trip o comparación equivalente;
4. sus bytes/metadata persistentes se reportan;
5. todo overhead persistente entra en B_core_actual.

Por tanto:

B_core_payload

sigue siendo exactamente 2,359,296 B, mientras:

B_core_actual

puede ser mayor.

El H0 futuro utiliza B_core_actual para razonamiento físico.

III. M1 — PRECISIÓN DE ACTIVACIONES
3. DECISIÓN: MISMA SEMÁNTICA CUANTIZADA PARA AVX2 Y AVX-VNNI

No autorizo comparar dos operadores matemáticos distintos bajo el mismo nombre de kernel.

Las dos rutas:

AVX2 baseline
AVX-VNNI optimized

deben implementar el mismo operador contractual.

3.1 Entrada lógica

La entrada suministrada al operador continúa siendo:

IEEE binary32

como ya define el contrato de fixtures.

3.2 Cuantización contractual de activación

Definir:

A_GROUP = 32
activation format = signed Q8 symmetric
range = [-127,+127]

Para cada fila de activación y cada grupo contiguo de 32 elementos:

a_max64
= max(abs(binary64(x_i)))

Si:

a_max64 = 0

entonces:

a_scale_fp32 = +0
q_a[i] = 0

En otro caso:

a_scale_exact64 = a_max64 / 127

a_scale_fp32
= IEEE binary32(
    a_scale_exact64,
    round-to-nearest ties-to-even
  )

Se usa después el valor exacto representado por a_scale_fp32:

a_scale_used64 = binary64(a_scale_fp32)

q_a[i]
= clamp(
    RNE(binary64(x_i)/a_scale_used64),
    -127,
    +127
  )

Una escala positiva que no pueda representarse de forma finita/no-cero en binary32 produce:

ACTIVATION_RANGE_ERROR

en un fixture de stress; no hay saturación silenciosa.

3.3 Dot product contractual

Para cada grupo correspondiente:

q_w ∈ [-7,+7]
q_a ∈ [-127,+127]

dot_i32
= Σ_32 q_a[i] * q_w[i]

La contribución física del grupo corresponde a:

dot_i32
× a_scale_fp32
× weight_scale_fp16

Los grupos se acumulan en orden ascendente de g.

La referencia independiente emula exactamente esta cuantización antes de formar su referencia numérica.

Las tolerancias existentes:

max_abs <= 2e-4
nRMS    <= 1e-4

se aplican contra este operador contractual cuantizado, no contra una matmul FP32 que omita la cuantización de activaciones.

3.4 AVX2

La ruta AVX2 implementa esta misma semántica.

Puede ensanchar:

q_a → int16
q_w → int16

y usar las primitivas AVX2 adecuadas.

No es una ruta FP32 matemáticamente distinta.

3.5 AVX-VNNI

Si AVX-VNNI está disponible, la ruta optimizada implementa la misma semántica usando la ruta signed-word compatible, por ejemplo:

VPDPWSSD de 256 bits

sobre valores sign-extended.

Para T0.0 no introducir una segunda semántica u8×s8 con zero-point/correcciones ocultas.

Una optimización futura de ese tipo requerirá especificación propia y revalidación de correctness.
